# Speculative Probing: LLM Monitoring at Speculative-Decoding Cost

Reference implementation for the paper *Speculative Probing: LLM Monitoring at
Speculative-Decoding Cost*.

**Idea.** Modern LLMs ship an auxiliary speculative-decoding head — a
co-pretrained Multi-Token-Prediction (MTP) layer in Qwen3.5, or a
post-hoc-distilled Eagle3 head in MiniCPM4.1. We freeze that head and the base
model, append `k` learned recursive soft-prompt vectors to the sequence, and read
a binary label from a small linear head over the head's pooled output. Only the
soft prompts + linear head are trained (~16K–20K parameters per task). During
speculative decoding the head's KV cache is already resident in GPU memory, so
classification adds negligible inference cost.

We denote our method with `k` recursive soft prompts as **SP-`k`** (SP-1, SP-2,
SP-5 in the paper).

## Repository layout

```
qwen35_mtp.py                    # Qwen3.5 MTP head module (frozen feature extractor)
minicpm_eagle3_wrapper.py        # MiniCPM4.1 Eagle3 head module
extract_qwen35_mtp.py            # pull the MTP tensors out of a full Qwen3.5 checkpoint
benchmark_gpt_zeroshot.py        # GPT zero-shot baseline (OpenAI API)

fast_softprompt/
  precompute_hidden_states.py        # cache base-model hidden states (verih / nemotron_safety)
  precompute_hidden_states_cot.py    # cache hidden states for the long-CoT tasks
  precompute_hidden_states_minicpm.py# MiniCPM variant (last / mid / 3-layer Eagle3 fusion caches)
  train_softprompt.py                # OUR METHOD on a Qwen3.5 MTP head
  train_eagle3_minicpm.py            # OUR METHOD on a MiniCPM4.1 Eagle3 head
  train_mlp.py                       # baseline: last-token MLP probe
  train_multimax.py                  # baseline: MultiMax probe (Kramár et al.)
  cache_io.py                        # (de)serialization for the mmap hidden-state caches
  eval_split.py                      # deterministic val/test split helper

prompts/                          # GPT zero-shot prompt template, one per task
verih/download_data.py            # build the verih dataset
nemotron_safety/build_classifier_dataset.py   # build the nemotron_safety dataset
cot_inconsistency/                # generate + label the two long-CoT datasets
scripts/run_qwen.sh               # one-command example: one Qwen3.5 model × one task
scripts/run_minicpm.sh            # one-command example: MiniCPM4.1 × one task
```

Large artifacts (base models, hidden-state caches, built datasets, results) are
regenerated by the pipeline and are **not** shipped; see `.gitignore`.

## Tasks and models

| Task                | Description                                   | Source dataset |
|---------------------|-----------------------------------------------|----------------|
| `verih`             | instruction contradiction detection           | VerIH |
| `cot_repetitive`    | repetitive-thinking detection in a CoT trace   | WebInstruct-verified traces, GPT-judged |
| `branched_thinking` | branched- vs. linear-thinking detection        | WebInstruct-verified traces, GPT-judged |
| `nemotron_safety`   | multilingual prompt safety                     | Nemotron-Safety-Guard-Dataset-v3 |

Models: **Qwen3.5-4B / 9B / 27B** (co-pretrained MTP head) and
**MiniCPM4.1-8B** (post-hoc-distilled Eagle3 head).

## Reproduction pipeline

Run everything from the repository root.

### Step 1 — Get the models and speculative-decoding heads

**Qwen3.5.** Download the base model, then extract its MTP tensors into a
standalone head directory:

```bash
# (download Qwen/Qwen3.5-4B into models/Qwen3.5-4B, or point --src at an HF cache)
python extract_qwen35_mtp.py \
  --src models/Qwen3.5-4B \
  --dst models/Qwen3.5-4B-mtp
# repeat for 9B and 27B
```

**MiniCPM4.1.** `openbmb/MiniCPM4.1-8B` and `openbmb/MiniCPM4.1-8B-Eagle3` are
downloaded from HuggingFace on first use. Point `E3DIR` at the extracted
`MiniCPM4_1-8B-Eagle3-bf16` directory inside the Eagle3 snapshot.

### Step 2 — Build the datasets

```bash
# verih
python verih/download_data.py                      # -> verih/data/{train,test}.json

# nemotron_safety
python nemotron_safety/build_classifier_dataset.py # -> nemotron_safety/classifier_dataset.jsonl

# cot_repetitive + branched_thinking (shared trace corpus, two labelings)
python cot_inconsistency/generate_labels_webinstruct_verified.py \
    --num-samples 18000 --dataset-split train --workers 20
#   -> cot_inconsistency/data/generated_webinstruct_verified_train_qwen3_5_plus.jsonl

python cot_inconsistency/label_generated_simpleqa_gpt_repetitive_thinking.py \
    --input cot_inconsistency/data/generated_webinstruct_verified_train_qwen3_5_plus.jsonl \
    --task repetitive_thinking --model gpt-5.4
python cot_inconsistency/label_generated_simpleqa_gpt_repetitive_thinking.py \
    --input cot_inconsistency/data/generated_webinstruct_verified_train_qwen3_5_plus.jsonl \
    --task branched_thinking --model gpt-5.4
#   -> ..._labeled_repetitive_thinking.jsonl  and  ..._labeled_branched_thinking.jsonl
```

### Step 3 — Precompute base-model hidden states (cache)

The precompute scripts run each base model **once** over the dataset and cache
per-token hidden states to disk (an mmap `<cache>.pt` + a large `<cache>.pt.hidden`
sidecar, plus a `<cache>_mid.pt` mid-layer cache used by the MultiMax baseline).
Classifier training then reuses the cache with no further base-model forward
passes. See `scripts/run_qwen.sh` / `scripts/run_minicpm.sh` for the exact
invocations, e.g.:

```bash
python fast_softprompt/precompute_hidden_states.py \
  --model Qwen/Qwen3.5-9B --task nemotron_safety --output cache_nemotron_safety_9b.pt \
  --num_train 10000 --num_test 1000 --max_length 2048 --batch_size 4 --mid_layer 16
```

### Step 4 — Train our method + baselines

```bash
python fast_softprompt/train_softprompt.py \
  --cache cache_nemotron_safety_9b.pt --mmap_cache \
  --mtp_dir models/Qwen3.5-9B-mtp --output_dir results/nemotron_safety_9b/sp1 \
  --soft_prompt_length 1 --recursive --classifier_head linear \
  --lr 3e-4 --min_lr 1e-4 --epochs 10 --batch_size 1 --dropout 0.2 --target_eval 800
```

Baselines: `train_mlp.py` (last-token MLP) and `train_multimax.py`
(MultiMax; reads the `_mid` cache). The MiniCPM Eagle3 head is trained with
`train_eagle3_minicpm.py --eagle3_dir "$E3DIR"`.

Each run writes `<output_dir>/final_results.json`; the best epoch is chosen by
validation accuracy and the reported number is the corresponding **test**
accuracy. `--target_eval T` sets the size of the held-out pool that is split
50/50 into val/test (645 for `verih`, 800 for `nemotron_safety`, 400 for the CoT
tasks, matching the paper).

### Step 5 — GPT zero-shot baseline (optional)

```bash
python benchmark_gpt_zeroshot.py \
  --task nemotron_safety --cache cache_nemotron_safety_9b.pt \
  --model gpt-5.4-mini-2026-03-17 --output results/gpt_zeroshot_nemotron.json
```

Uses the same cached test split, and the per-task prompt template in `prompts/`.

## One-command examples

```bash
E3DIR=/path/to/MiniCPM4_1-8B-Eagle3-bf16 bash scripts/run_minicpm.sh cot_repetitive
```

## Hyperparameters (from the paper)

- **SP-`k` (ours):** AdamW, lr `3e-4` cosine-decayed to `1e-4`, weight decay
  `0.01`, batch size 1, sigmoid linear head, dropout `0.2` on the pooled hidden
  state, `k ∈ {1, 2, 5}`. 10 epochs on `verih`/`nemotron_safety`, 4 epochs on the
  two CoT tasks.
- **MLP probe:** AdamW, lr `5e-4`, batch size 32, 10 epochs, hidden dim 2048.
- **MultiMax probe:** `H = 10` heads, MLP width 100, mid-layer hidden states,
  same optimizer schedule as the MLP probe.

## Hardware

Experiments were run on 2× NVIDIA RTX PRO 6000 Blackwell (96 GB each).
Precomputing hidden states and holding the base model dominate GPU memory;
classifier training itself is tiny (only the soft prompts + linear head are
updated).
